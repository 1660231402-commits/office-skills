# Life Report — 生活复盘自动化

把用户每天讲述的事件落成结构化记录，再按周期生成带分析与鼓励的 HTML 报告邮件。所有数据保存在本 skill 的 `data\` 目录下。

## 目录结构

```
life-report/
├── config.json               # 邮箱配置（用户需填 SMTP 授权码，未配置时脚本会友好提示）
├── scripts/
│   ├── send-mail.ps1         # 发送邮件：-mode test|reminder1|reminder2|missed|report
│   ├── check-recorded.ps1    # 检查某日期是否已有事件记录（默认昨天），输出 RECORDED/MISSING
│   ├── collect-events.ps1    # 汇总日期区间的事件数据（结构化文本输出）
│   ├── pick-quote.ps1        # 从名言库随机选一条（可按主题）
│   ├── transcribe.ps1        # 语音转文字（离线中文引擎，仅 PCM wav）
│   └── read-docx.ps1         # 提取 .docx 文档正文文本
├── assets/
│   ├── report-template.html  # 报告 HTML 模板（占位符说明在文件头注释里）
│   └── quotes.json           # 名言库（43 条，含主题标签）
└── data/
    ├── events/               # 每日事件：YYYY-MM-DD.md（唯一事实来源）
    ├── reports/              # 生成的报告 HTML
    └── state.json            # 已发送记录（幂等，防重复发送）
```

环境：Windows 自带 PowerShell 5.1，无其他依赖。所有命令都在本 skill 根目录下执行：

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\send-mail.ps1 -mode test
```

## 工作流 A：记录事件（支持文字 / 文件 / 语音）

触发语示例：「记录事件：今天……」「把 D:\notes\日记.docx 记进去」「听一下这段录音，补发昨天」「修改 9 月 10 日的记录：……」。

### 第一步：按来源获取事件内容

**① 文字输入**：用户直接打字（或按 Win+H 用 Windows 语音输入对着对话说），文字即事件内容。

**② 文件输入**：用户给出文件路径或把文件拖进对话。按类型提取文字：

- `.txt` / `.md` / `.html` 等文本：直接用 Read 读取。
- `.docx`：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\read-docx.ps1 -File "<路径>"`。
- 图片（日记照片、聊天截图）：用 Read 直接查看并读出内容。
- `.pdf`：先尝试 Read；读不了就请用户截图或复制文字过来。
- 文件里有日期线索（日记标题、日期行、文件名）时，以它为记录日期；文件较长时只提取「发生的事」，不要全文照搬。

**③ 语音输入**：

- PCM wav 音频文件：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\transcribe.ps1 -File "<路径>"`，输出 `TEXT: <转写文字>`。本机离线引擎准确度有限，**必须把转写结果展示给用户确认/更正后再写入**。
- `mp3 / m4a / amr` 等其他格式暂不支持离线转写，引导用户：①按 Win+H 直接对对话说话；②手机输入法语音转文字后发文字；③转成 wav 再发。
- 语音内容口语化，整理时按下面第三步合并为要点，不改事实；听不清处以「（听不清）」标注，确认后仍不清的不要写入。

### 第二步：确定日期

用户指定了日期（补发）→ 用指定日期；文件里有明确日期线索 → 按线索；否则用今天 `Get-Date -Format yyyy-MM-dd`。

### 第三步：整理并写入

**写入文件** `data\events\<日期>.md`，格式固定为：

```markdown
# 2026-09-12

## 重点事件
- 一句话概括 + 简短说明

## 好事情
- ……

## 坏事情
- ……

## 补充
- 心情、想法、想记住的话（可选）
```

1. **合并不覆盖**：文件已存在时保留已有条目，把新内容追加到对应小节，绝不删减原有记录。用户没提到的小节直接省略。
2. **补发标记**：补发时在标题行下加一行（已加过则不重复）：`> 补录于 <今天的日期>`。
3. 把口语/文件/转写内容整理成小节要点，可轻度润色，但不改变事实、不添加用户没说的事。
4. **回复用户**：确认已记录 + 一句**具体**的即时鼓励（引用用户说的事情本身，不说空话）。
5. 若补发/修改的日期其日报已发送（`data\state.json` 中已有 `<日期>_日报`），告知用户：该日日报已发过，本次内容会自动并入之后的周报/月报分析。

### 修改已有记录

用户说「修改 / 更正 / 补充 X 日的记录：……」时：

1. 读取 `data\events\<X>.md`（不存在则提示按新建流程记录）。
2. 按用户指示增 / 删 / 改对应条目，**其余条目原样保留**；用户明确说「重写」才允许整段替换。
3. 回复修改后的记录摘要，让用户确认。

## 工作流 B：生成报告

触发：定时任务（见文末时间表）或用户手动要求（「生成今天的日报」「出一份上周周报」）。定时任务运行时**不要向用户提问**，按本流程直接执行，遇到问题记录后结束。

### 类型、命名与发送时间

| 类型 | 覆盖期间 | tag / 文件名 | 自动化发送时间 |
|---|---|---|---|
| 日报 | 单日 | `<覆盖日>_日报`，如 `2026-09-12_日报` | 次日 08:00 |
| 周报 | 上周一 ～ 周日 | `<周期末日>_周报`，如 `2026-09-13_周报` | 周一 08:00 |
| 月报 | 上一自然月 | `<YYYY-MM>_月报`，如 `2026-08_月报` | 每月 1 日 08:00 |
| 半年报 | 1-6月 / 7-12月 | `2026-H1_半年报` / `2025-H2_半年报` | 7月1日 / 1月1日 08:00 |
| 年报 | 上一自然年 | `<YYYY>_年报`，如 `2025_年报` | 1月1日 08:00 |

文件名与 tag 一律以**覆盖期间**命名（周报用周期最后一天）。邮件主题示例：`生活周报 | 2026-09-07 ~ 09-13`。该时间表保证任何报告都在周期结束后**第二天内**送达。

定时任务只有一个自动化（每天 08:00 / 10:00 / 20:00 / 22:00 触发），按当前小时分派：08:00 时段负责所有报告生成，周报/月报/半年报/年报按日历条件（周一 / 1日 / 1月1日·7月1日）在同一次触发中一并生成，state.json 幂等防止重复发送。

### 步骤

1. **幂等检查**：读 `data\state.json`，若本次 tag 已存在 → 回复「已发送过」，结束。
2. **收集数据**：
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\collect-events.ps1 -from 2026-09-07 -to 2026-09-13
   ```
   输出每个日期各小节的要点与统计（日报可用 `-date 2026-09-12`）。
3. **空数据处理**：日报若 `DAYS_WITH_RECORDS` 为 0 → 跳过发送，结束（10 点的补发检查会提醒用户）。周报及以上即使记录很少也照常生成，并如实说明「本期仅记录 N 天」。
4. **撰写内容**（规范见下节）。
5. **选名言**：
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\pick-quote.ps1 -theme 坚持
   ```
   主题按本期最突出的内容选（如坏事情多 → 挫折/勇气；好事情多 → 成长）。`QUOTE_NOTE` 用一句话把名言与本期内容连起来；避免与最近一期报告重复同一条。
6. **填充模板**：复制 `assets\report-template.html` 到 `data\reports\<tag>.html`，替换全部 `{{...}}` 占位符，删除模板头部注释；保持 CSS 与结构不动。列表按模板头注释里的「列表规范」渲染：小节列表用带序号的 `<li>`（01/02/… 递增，灰字衬线序号 + 底部细线）；某小节无内容时只写一行「本期无记录」；「改善建议」列表用左侧 2px 黑竖线的 `<li>` 样式。
7. **发送**：
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\send-mail.ps1 -mode report -file "data\reports\<tag>.html" -subject "生活周报 | 2026-09-07 ~ 09-13" -tag "<tag>"
   ```
   脚本发送成功后自动把 tag 写入 `state.json`；若输出 `ALREADY_SENT` 表示此前已发过，不要重复处理。
8. **回复用户**：报告要点摘要（2-3 句）+ 已发送确认。

### 写作规范

- 只基于事件原文分析，可引用原话；**不编造**用户没记录的事。
- 坏事情用建设性语气：现象 → 影响 → 改善方向，不指责、不评判。
- 分析结构：总体概括 → 亮点（把好事情放大）→ 挑战 → 规律/模式 → 1~3 条改善建议。
- 改善建议必须**具体可执行**：「今晚 22:30 把手机放到客厅充电」，而不是「要早点睡」。
- 鼓励要具体、真诚，落在用户真实做到的事情上。
- 篇幅：日报分析 150~300 字；周报 300~500 字；月报 500~800 字；半年报/年报 800~1500 字（叙事化回顾 + 成长轨迹 + 下阶段建议）。
- 周期越长的报告越要做**跨天规律分析**（比如「连续三周周三都漏记录」），而不是把日报简单拼起来。

## 工作流 C：提醒与补发检查（已由定时任务触发，也可手动执行）

定时任务每天 08:00 / 10:00 / 20:00 / 22:00 触发一次，按小时分派：

| 时段 | 行为 |
|---|---|
| 每天 20:00 | 提醒记录今天的事件（reminder1） |
| 每天 22:00 | 最后一次提醒（reminder2） |
| 每天 10:00 | 检查**昨天**是否有记录；缺失才发 missed 提醒 |
| 每天 08:00 | 生成并发送昨天日报；逢周一 / 1日 / 1月1日·7月1日 同时生成周报 / 月报 / 半年报·年报 |

手动执行：

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\send-mail.ps1 -mode reminder1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\send-mail.ps1 -mode reminder2
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check-recorded.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\send-mail.ps1 -mode missed
```

补发检查的判定：`check-recorded.ps1` 输出 `RECORDED` → 不发任何邮件；输出 `MISSING` → 再执行 `-mode missed` 发送补发提醒。提醒邮件按「日期+类型」自动幂等，同一天同一种提醒只发一次。

## 邮箱配置

`config.json`：

```json
{
  "smtp": {
    "host": "smtp.qq.com",
    "port": 465,
    "ssl": true,
    "starttls": false,
    "username": "你的邮箱@qq.com",
    "password": "SMTP授权码（不是登录密码）",
    "sender_name": "生活复盘助手"
  },
  "to": ["接收报告的邮箱"]
}
```

常用邮箱：QQ `smtp.qq.com:465(SSL)`；163 `smtp.163.com:465(SSL)`；Gmail `smtp.gmail.com:465(SSL)`；Outlook `smtp.office365.com:587(STARTTLS，设 ssl=false、starttls=true)`。

QQ 授权码：网页版邮箱 → 设置 → 账户 → 开启「POP3/IMAP/SMTP 服务」→ 生成授权码。163：设置 → POP3/SMTP/IMAP → 开启服务 → 新增授权密码。

配置后务必先测试：`send-mail.ps1 -mode test`。

## 注意事项

- 发送失败时脚本会打印服务器返回的原因；常见：授权码错误、端口/SSL 配置不匹配、收件人地址错误。最多重试一次，仍失败就告知用户，不要反复重试。
- 邮箱未配置（config.json 仍是占位符）时脚本以退出码 2 结束并给出指引；此时不要重试，等用户配置。
- 所有日期用本地日期；`data\events\` 是唯一事实来源，报告是派生物，不回写事件文件。
- 需要强制重发某期报告：编辑 `data\state.json` 删除对应 tag，再走工作流 B。
- 每封报告邮件 = HTML 正文（邮箱里直接可看）+ HTML 附件（下载后浏览器打开），满足"线上查看"的要求。
